## 結論

**作成する。**

Javaの文字列解析という近接領域の既存記事は確認できましたが、`String.split`の既定limitによる**末尾空トークンの破棄**を直接原因として、空の任意列を持つ入力の受理結果と最終状態を扱う記事・教材は見つかりませんでした。

既存のHTTPie記事とは、原因が「エスケープされた複数文字トークンの境界」であるか「既定limitによる末尾空文字列の除去」であるかが異なります。実境界はCLIパーサーか純粋Javaサービスか、観測契約はキー・値の分解か受理済み行と拒否件数か、最小修正は字句走査か`split`のlimit指定かという四軸で区別できます。
